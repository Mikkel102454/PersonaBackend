# Visual editor usability and performance budgets

Status: accepted Phase 0 quality gate. Measurements use a production-like browser at
100% and 200% zoom after one warm run. CI records median and p95 where practical.

## Bounded representative fixtures

Fixtures live under `src/test/resources/visual-editor/` or are deterministically
generated by the named test builder; generated fixtures use a fixed seed.

| Fixture | Shape | Purpose |
| --- | --- | --- |
| `all-content-kinds` | 3 of each resource kind, every built-in node/step/condition/command/objective, signed extension examples, references and custom YAML | mapping, round trip, creation, navigation |
| `large-project` | 2,000 files, 10 MiB total, 12,000 typed references, 10% unresolved | content browser, relationship map, project operations |
| `large-behaviour` | 2,000 nodes, 1,999 containment edges, depth 64 | projection, layout, pan/zoom, mutation |
| `dense-dialogue` | 1,000 entries, 4,000 transfer/choice edges | wire rendering, diagnostics, minimap |
| `deep-script` | supported nesting limit 32 with every branch kind | source ranges, palette, keyboard navigation |
| `lossless-yaml` | block/flow scalars, comments, blanks, quotes, tags, anchors, aliases, merge keys, unknown and extension fields | Custom YAML boundary and byte preservation |

Requests exceeding server-configured byte, file, node, edge, operation, nesting, or
rate limits fail with structured errors and do not partially mutate state. Test
fixtures may be scaled down only on constrained developer machines; CI uses the full
accepted bounds.

## Performance budgets

| Operation | Fixture | Budget |
| --- | --- | --- |
| authenticated project index | `large-project` | p95 ≤ 1,500 ms server; first useful browser render ≤ 2,000 ms |
| open/project graph projection | `large-behaviour` | p95 ≤ 1,000 ms server, ≤ 1,500 ms browser render |
| warm tab switch | any open resource | p95 ≤ 100 ms to visible cached projection |
| search/filter keystroke | `large-project` | p95 ≤ 100 ms; no lost input |
| pan/zoom/drag | `large-behaviour`/`dense-dialogue` | ≥ 50 fps median, no frame > 100 ms during a 5 s gesture |
| wire geometry batch | `dense-dialogue` | ≤ one update per animation frame; p95 frame work ≤ 12 ms |
| scalar graph mutation | ordinary fixture | p95 ≤ 300 ms server and ≤ 500 ms acknowledgement-to-render |
| structural/compound mutation | `large-behaviour` | p95 ≤ 750 ms server and ≤ 1,000 ms acknowledgement-to-render |
| deterministic auto-layout | `large-behaviour` | ≤ 2,000 ms; identical input gives identical positions |
| relationship-map analysis | `large-project` | p95 ≤ 1,500 ms server, progressive browser render ≤ 2,000 ms |
| idle workspace memory | `large-project`, 10 open tabs | ≤ 256 MiB browser heap after GC |

No viewport, selection, or layout-only interaction may reparse the complete project or
send a content mutation request.

## Usability budgets

- A keyboard-only user opens any indexed resource in at most five actions after
  `Ctrl/Cmd+P`, creates a compatible connected node in at most eight, and reaches the
  exact YAML range for an error in at most three.
- Connection loss disables every editing surface within 250 ms of socket/session
  failure notification. No cached editable workspace is shown while disconnected.
- Focus remains visible at all times and returns to the invoking control after dialog,
  palette, or drawer close.
- At 320 CSS pixels width and at 200% zoom, creation, editing, validation navigation,
  reconnect, export, and publish review have no unreachable controls.
- Pointer targets are at least 24 by 24 CSS pixels, with 44 by 44 preferred for primary
  touch actions. Pins have a larger invisible hit target without changing wire origin.
- Every pointer graph operation has a documented keyboard equivalent and an accessible
  status/error announcement.

## Reliability and test gates

- Golden tests prove bytes outside reported edit ranges are identical.
- Property tests run at least 10,000 generated bounded graph mutations per CI build.
- Browser suites cover Chromium and one non-Chromium engine; accessibility includes
  automated rules plus keyboard, screen-reader semantics, forced colors, reduced
  motion, and 200% zoom assertions.
- Security suites cover forged layouts, malicious paths/IDs/YAML, stale digests,
  unauthorized sessions, schema/catalog abuse, and every configured bound.
- A phase cannot claim its exit criterion while a required budget lacks a test or a
  recorded, reviewed exception in a superseding ADR.
